# Проверки выпуска 1.0.0

Дата: 27 октября 2026 г. Рабочие роутеры не использовались; сетевые сбои на них не создавались.

## Выполнено локально

* **35 проверок на Windows / 37 на Linux** `tests/run.cjs`: синтаксис шести shell-файлов и LuCI JavaScript, точный набор ACL, меню, IPv4/TLS/таймауты curl, независимые ресурсы, корректная трактовка 403/404, DNS/общесетевые сбои, 5xx и ошибки сертификатов, безопасный UNKNOWN, валидация адреса/пользователя SSH и строгого ответа клиента, wiring procd/respawn/UCI trigger с подставными функциями, повторный тест, лимиты 900/3600 секунд, остановленный Zapret2, гистерезис из двух успешных проверок, учёт неуспешных попыток, отказ восстановления при невозможности сохранить состояние, фильтрация и порядок компактного журнала. Две дополнительные Linux-проверки проверяют настоящую kernel flock: запрет параллельного захвата и освобождение блокировки после выхода процесса.
* **Пять изолированных сценариев установщика** `tests/install.cjs`: OpenWrt 24.10/opkg, OpenWrt 25.12/apk, обновление с сохранением UCI, откат прежних файлов/состояния службы при ошибке регистрации RPC, повторная установка без переустановки уже имеющихся зависимостей. Пакетные менеджеры, служба, ubus, UCI, JSON-фильтр и блокировки в этих сценариях имитируются; реальные команды скачивания заменяются копированием тестового комплекта. Реальная сверка SHA256SUMS и размещение файлов выполняются в изолированном каталоге.
* Реальный `files/overview.js` выполнен в Chromium с минимальной имитацией LuCI/RPC: старт, остановка, однократный check, переключение автозапуска, обновление состояния. Компьютерная ширина 1050 и мобильная 390 px, без ошибок JavaScript и горизонтального переполнения. Скриншоты проверены визуально. Данные журналов в предпросмотре демонстрационные.

Тесты выполнялись Node.js 24 и BusyBox-w32 ash на Windows, а также Node.js 22 и /bin/sh на Ubuntu в GitHub Actions. Linux-проверка shell/фикстур и контрольных сумм прошла успешно: [запуск проверки](https://github.com/TMN88/youtube-watchdog/actions/runs/40564791555). Тесты не делают реальных запросов YouTube/DNS и не вызывают системные службы. Актуальный запуск текущего commit доступен во вкладке Actions.

```sh
node tests/run.cjs
node tests/install.cjs
sha256sum -c SHA256SUMS
```

На Windows для shell-проверок задайте `BUSYBOX` в путь к BusyBox-w32. Node нужен только разработчику, на роутер не устанавливается.

## Исправление установщика 1.0.1 — 28 октября 2026

Причина: реальный запуск на cudy_wr3000s_7 остановился с ошибкой «Не найдена команда timeout» до установки зависимостей. Наличие applet в BusyBox не гарантируется конкретной сборкой OpenWrt.

Вместо раннего отказа установщик добавляет штатный `coreutils-timeout`, только когда `command -v timeout` неуспешен, и проверяет команду повторно до изменения файлов службы. Четыре адресных regression-сценария прошли локально: отсутствие timeout на opkg, отсутствие timeout на apk, отказ установки пакета и отсутствие команды после формально успешной установки. Последние два сценария подтверждают отказ до размещения службы и включения автозапуска. Выполнены только изменённые сценарии (`YW_INSTALL_CASE=timeout`); аппаратный результат исправленной установки ещё не подтверждён.

## Исправление установщика 1.0.2 — первая проверка после установки

Изолированный тест воспроизвёл удержание установщиком operation.lock во время запуска службы: начальная проверка не могла захватить блокировку. После освобождения блокировки перед `init start` два адресных сценария opkg/apk прошли. Остальные компоненты службы не изменялись.

На cudy_wr3000s_7 пользователь подтвердил установку 1.0.1 с работающими Watchdog/procd и Zapret2; ручной `youtube-watchdog check` вернул local_probe=HEALTHY и заполнил checked_at. Клиентский статус остался UNKNOWN в безопасном режиме. Это подтверждает ручной локальный probe и сохранение результата на этом роутере, но не проверку LAN-пути, автоматическое восстановление или отображение LuCI.

## Настройка интервала 1.1.0

Добавлены 14 адресных RPC-проверок: границы 3/1440 минут, обычное сохранение, отсутствие повторной записи того же значения, отклонение дробей/строк/отрицательных/слишком больших/пропущенных значений и инъекций, сообщение об ошибке commit. Проверяется запись только youtube-watchdog.main.interval и уведомление работающего демона. Два сценария планировщика проверяют уменьшение и увеличение интервала во время текущего ожидания. Служебные проверки: 37 Windows / 39 Linux с учётом новых сценариев.

Реальный JavaScript view проверен в отдельном Chromium с имитацией LuCI/RPC: сохранение 5 минут, защита от двойного клика, валидация, ошибка сервера, сохранение незавершённого ввода при polling, запрет изменений для сессии без write-прав, отдельная строка локальной диагностики, мобильная ширина 390 px без переполнения. Предпросмотр и снимки обновлены из реального view. Запуск: node tests/settings.cjs; node tests/ui.cjs (для UI нужен Playwright и локальный Chrome; на роутер они не устанавливаются).

## Статус и фиксированные интервалы 1.2.0

Главная карточка показывает результат с явным источником «роутер» или «LAN-клиент», без отдельной строки локальной проверки. Поле client_youtube и внутренняя логика восстановления остаются консервативными: локальный HEALTHY не разрешает перезапуск. Добавлены четыре адресных сценария: доступный роутер при неизвестном клиентском пути, просроченный результат, отказ LAN при доступном роутере и отображение ошибки DNS. Всего 41 проверка службы Windows / 43 Linux.

Настройка интервала теперь содержит ровно восемь вариантов 1, 3, 5, 7, 10, 15, 20, 30 минут. 20 RPC-сценариев проверяют все варианты, запрет других значений и типов, отсутствие повторной записи и ошибку сохранения. Проверена поддержка 60 секунд в демоне. Chromium-проверка подтверждает состав списка, сохранение выбора при polling, отсутствие удалённой строки, подписи источника для router/LAN и мобильный вид. Новая версия на роутере пока не проверялась.

## Активное восстановление с роутера 1.3.0

По прямому требованию пользователя прежний основной режим наблюдения заменён на router: локальный подтверждённый отказ разрешает штатный restart работающего Zapret2. Используется только range/UA/low-speed способ из Site_Checker (files/sitecheck-check-zapret, commit ed1e31ac4e5e8fa662532b58bf7fb6dbf89375b7); обычного второго запроса нет. TLS, IPv4, контрольный HTTPS, DNS и ресурсный кворум сохранены. Подтверждающий повтор теперь через 30 секунд, контроль после команды — через 15 секунд.

49 локальных проверок службы (51 Linux) включают реальную ветку решения router с подставными сетевыми результатами: отказ/отказ/восстановлен, восстановление на подтверждении, ошибки DNS/интернета/неопределённость, намеренно остановленный Zapret2. Проверяется точный набор range/UA/low-speed/таймаутов, включая успешный ответ HTTP 206. Дополнительно прошли адресные сценарии обновления safe → router с сохранением интервала и отката конфигурации при ошибке. Интерфейс проверен с recovery_enabled=true. На настоящем роутере сбои не создавались; автоматический restart новой версии аппаратно ещё не подтверждён.

## Не подтверждено аппаратным испытанием

Настоящие установка/обновление пакетов opkg и apk, загрузка через procd после перезагрузки, регистрация RPC в штатном rpcd, разрешения реальной сессии LuCI, сочетания тем Argon/Footstrap/Aurora и реальный клиентский путь с Zapret2. В этих пунктах реализованы стандартные файлы и интерфейсы OpenWrt, но локальные моки не доказывают совместимость оборудования.

Перед включением режима SSH требуется отдельная проверка оператором на подходящем тестовом стенде. Без неё безопасный режим остаётся полноценным вариантом эксплуатации с UNKNOWN и без перезапусков. Успешные HTTPS endpoints не доказывают воспроизведение видео.
