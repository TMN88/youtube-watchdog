# YouTube Watchdog

Версия приложения **1.4.1** для OpenWrt 24.10/opkg и 25.12/apk. Проверяет YouTube с роутера и при подтверждённом отказе перезапускает выбранный работающий Zapret/Zapret2 с ограничением попыток.

## Установка и обновление через общий установщик

Команда остаётся прежней:

```sh
wget -O /tmp/install_packets_script.sh \
  https://raw.githubusercontent.com/TMN88/install_packets_script/main/openwrt-toolkit.sh \
  && sh /tmp/install_packets_script.sh
```

Выберите **9 — YouTube Watchdog**. Начиная с toolkit 2.0.3 этот пункт проверяет обновление даже при уже установленном приложении. Повторный запуск актуального комплекта не заменяет файлы и не перезапускает службу.

Обновление выполняет `update.sh`: загружает комплект с закреплённого commit, проверяет SHA256SUMS, shell/JSON и версию, сохраняет backup с ручным rollback, затем атомарно заменяет файлы. При ошибке восстанавливает прежний комплект. Пользовательский UCI, engine, интервал, режим и прежние running/enabled сохраняются; понижение версии запрещено. Backup: `/etc/youtube-watchdog-backups/update.*`. Команда возврата печатается после обновления.

Исторический `install.sh` сохранён без изменений по требованию совместимости. Он закреплён на 1.3.1 и **не является текущим обновлятором**. Не используйте его для получения новых версий; существующая команда общего установщика выше вызывает текущий `update.sh`.

## Возможности

- Версия приложения в LuCI → Службы → YouTube Watchdog.
- Красное выделение ошибок и зелёное выделение успешных записей.
- Раскрываемый журнал с прокруткой и скачиванием доступной истории за последние 72 часа. История хранится в RAM, после перезагрузки начинается заново. В интерфейсе показываются последние 100 записей, экспорт содержит весь сохранённый трёхсуточный журнал.
- В журнале HTTP/curl, длительность, DNS, причины ожидания/пропуска, команды восстановления и контрольный результат. Сырые подписанные URL и ключи не записываются.
- Стандартный интервал новых установок **10 минут**. При обновлении выбранный пользователем интервал сохраняется.
- Поддержка явных `engine=zapret` и `engine=zapret2`; новая установка использует `engine=auto`. При неоднозначном выборе auto восстановление не выполняется. На прежних конфигурациях без engine сохраняется совместимость с Zapret2.

## Проверка и восстановление

Router-режим проверяет HTTPS с самого роутера; HEALTHY не доказывает LAN-воспроизведение или работоспособность всех видеопротоколов. Отказ подтверждается повторной проверкой через 30 секунд. Ограничение восстановления: минимум 15 минут между попытками и максимум три за час. Сохраняющийся отказ допускает новую попытку после cooldown; бессрочной блокировки после первого restart больше нет.

Намеренно остановленный движок не запускается. Сбои DNS, общего интернета и неопределённый результат запрещают восстановление. Для HTTPS используется проверка сертификата, IPv4, отключены proxy/curlrc, timeout запроса 25 секунд, подключения 5 секунд, low-speed 10 секунд. SSH/LAN-режим остаётся дополнительным сценарием: [CLIENT.md](CLIENT.md).

Команды:

```sh
youtube-watchdog status
youtube-watchdog check
youtube-watchdog logs
```

`check` обновляет измерение и не выполняет восстановление. Фоновый daemon выполняет цикл восстановления. Поддержка v1 и границы испытаний: [ZAPRET1-SUPPORT.md](ZAPRET1-SUPPORT.md). Исторические отчёты: [VALIDATION.md](VALIDATION.md), [HARDWARE-VALIDATION.md](HARDWARE-VALIDATION.md).

## Проверки разработки

`node tests/run.cjs`, `node tests/settings.cjs`, `node tests/install.cjs`, `node tests/update.cjs`. Установочные тесты работают с изолированной файловой системой и имитацией OpenWrt-служб/сети. Это отдельная проверка от реального обновления на роутере.
