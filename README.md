# YouTube Watchdog • TMN88

Служба OpenWrt **24.10.x / opkg** и **25.12.x / apk** с русским интерфейсом **LuCI → Службы → YouTube Watchdog**. Проверяет сам YouTube с роутера и при повторно подтверждённом отказе штатно восстанавливает запущенный или аварийно упавший Zapret2. Намеренно остановленная служба не запускается.

**Выпуск 1.3.1:** исправлены скрытие отказа основного YouTube вспомогательными ресурсами и запрет восстановления аварийно упавшего процесса. Отдельно исправлено наследование daemon.lock дочерними процессами, мешавшее respawn Watchdog. Проверено боевыми тестами на Netis N6 V2 / OpenWrt 25.12.5: [результаты](HARDWARE-VALIDATION.md). Автовосстановление с роутера включено по умолчанию; отдельный LAN-клиент не нужен. Прежний режим `safe` при установке заменяется на `router`, интервал сохраняется.

## Установка и обновление

```sh
wget -O /tmp/youtube-watchdog-install.sh https://raw.githubusercontent.com/TMN88/youtube-watchdog/main/install.sh && sh /tmp/youtube-watchdog-install.sh
```

Выполнять от root. Установщик определяет opkg/apk, ставит только недостающие `curl ca-bundle flock rpcd luci-base` и при отсутствии timeout — `coreutils-timeout`. Загружает закреплённый commit комплекта 1.3.1, сверяет SHA256SUMS, проверяет shell/JSON, регистрирует RPC, включает автозапуск и запускает Watchdog. Существующий UCI сохраняется, кроме явного перевода прежнего `safe` в `router`. При ошибке применения восстанавливаются старые файлы, конфигурация и прежнее состояние службы. Общие зависимости не удаляются.

После обновления перезагрузите страницу LuCI. Интервалы: **1, 3, 5, 7, 10, 15, 20, 30 минут**, по умолчанию 3 минуты. Кнопка «Сохранить интервал» применяет изменение без перезапуска службы; уже выполняющаяся проверка не прерывается. Тот же интервал повторно не записывается на flash. Установщик освобождает блокировку проверки перед запуском procd.

## Проверка YouTube

Используется **только способ из [Site_Checker / sitecheck-check-zapret](https://github.com/TMN88/Site_Checker/blob/ed1e31ac4e5e8fa662532b58bf7fb6dbf89375b7/files/sitecheck-check-zapret)**: следование HTTPS-редиректам, диапазон `0–65535`, User-Agent `Mozilla/5.0 (Windows NT 10.0; Win64; x64) curl/8.0`, контроль минимальной скорости 1 байт/с в течение 3 секунд, подключение до 3 секунд и запрос до 5 секунд. Обычного второго способа нет. Адаптация сохраняет проверку TLS/имени узла, IPv4, запрет перехода на HTTP и обход переменных прокси; curlrc не читается.

Проверяется именно `https://www.youtube.com/`, как в Site_Checker. Ответы `i.ytimg.com` и API больше не подменяют его результат. Проверяются DNS YouTube и контрольного сайта; при отказе YouTube дополнительно выполняется внешний HTTPS-контроль `https://example.com/`. Успешный прямой запрос YouTube не становится ошибкой из-за независимого контрольного сайта.

* Доступен: curl к самому `www.youtube.com` завершился успешно и получил корректный HTTP-код. Как в Site_Checker, это подтверждение HTTP-доступности, а не содержимого страницы или воспроизведения видео; HTTP 4xx/5xx сам по себе не является обрывом транспорта.
* Отказ YouTube: транспортная ошибка/таймаут самого `www.youtube.com` при исправных DNS и контрольном HTTPS. Ошибка сертификата или неполный результат дают неопределённость и не разрешают восстановление.
* Для внешнего контроля подходят ответы 2xx/3xx; 403/404 не считаются успехом контроля.
* Ошибка DNS или контрольного сайта блокирует перезапуск Zapret2.

Карточка **«YouTube · роутер»** показывает доступность с роутера, а не доказательство воспроизведения видео на каждом телефоне/компьютере. Не гарантируются работа googlevideo CDN, конкретного ролика и совпадение правил OUTPUT с LAN/FORWARD. Автовосстановление намеренно основывается на router-local проверке по текущему требованию пользователя. Поле `client_youtube` остаётся UNKNOWN без отдельного измерения с LAN.

## Когда перезапускается Zapret2

1. Проверка обнаруживает подтверждённый отказ YouTube при рабочем интернете и DNS.
2. Watchdog ждёт **30 секунд** и повторяет всю проверку тем же способом.
3. Если отказ повторился, проверяет состояние procd и лимиты. Сохранённая procd-регистрация при погибшем процессе означает аварийный сбой; отсутствие экземпляров после `init stop` — намеренную остановку.
4. Выполняет `/etc/init.d/zapret2 restart` с таймаутом 40 секунд.
5. Через **15 секунд** запускает контрольную проверку и пишет результат в журнал.

Намеренно остановленный или отсутствующий Zapret2 не запускается. Аварийно завершившийся зарегистрированный процесс восстанавливается, даже когда `init running` возвращает ошибку. Минимум **15 минут** между попытками, максимум **3 за скользящий час**; неудачная команда тоже расходует лимит. После попытки включается гистерезис: для повторного разрешения восстановления нужны две последовательные успешные фоновые проверки. До этого мониторинг продолжается без новых перезапусков. Пропущенный из-за занятой блокировки цикл не засчитывается как успешный.

Служба не меняет стратегии Zapret2, firewall, маршруты, DNS и другие обходы. Не запускает Blockcheck2 и не перезагружает роутер. Остановка Watchdog не останавливает Zapret2. Синхронизация — kernel flock; runtime, лимиты и уведомления — в `/tmp`, события — в кольцевом logread. Монотонное время защищает лимиты от перевода часов. Перезагрузка роутера очищает RAM-состояние.

## Команды

```sh
/etc/init.d/youtube-watchdog start
/etc/init.d/youtube-watchdog stop
/etc/init.d/youtube-watchdog restart
/etc/init.d/youtube-watchdog enable
/etc/init.d/youtube-watchdog disable
youtube-watchdog check   # один тест, НИКОГДА не вызывает restart
youtube-watchdog status
youtube-watchdog logs
logread -e youtube-watchdog-event
```

`status` возвращает версию, отображаемый `youtube`, источник `youtube_scope`, локальный результат `local_probe`, `recovery_enabled`, состояние `zapret_state` (running/crashed/stopped), время и интервал. LuCI различает «Сбой процесса» и «Остановлен». Во время `check` блокировка ещё может быть занята в момент вывода ответа; отдельный последующий `status` отражает текущее состояние. Основной цикл запускается сразу при старте и затем ждёт выбранный интервал после окончания проверки. Время запросов прибавляется к периоду между началами циклов.

LuCI использует те же RPC/CLI-функции, обновляет состояние динамически и запрещает двойные действия. Журнал содержит только попытки перезапуска Zapret2 с причиной/статусом и результат контрольной проверки: восстановлен / не восстановлен / неизвестно. Последние 20 событий, новые сверху; обычные успешные проверки, сырой curl и чужие службы не выводятся. После очистки logread история может быть пустой.

## UCI

```uci
config watchdog 'main'
    option mode 'router'
    option interval '180'
```

LuCI/RPC разрешают только восемь указанных интервалов. Для совместимости демон принимает старые пользовательские значения от 60 до 86400 секунд; нестандартное старое значение сохраняется до выбора нового. RPC записи ограничен единственным параметром интервала; нет доступа к произвольным файлам, командам или настройкам других служб.

Режим `safe` оставлен как явный ручной отказ от восстановления после установки: он только наблюдает. Повторная установка переводит прежний `safe` в `router`, как описано выше. Существующий `ssh` сохранён как необязательный режим для заранее настроенного LAN-клиента ([CLIENT.md](CLIENT.md)); обычной установке он не нужен.

## Удаление

```sh
sh /usr/libexec/youtube-watchdog-uninstall
```

Удаляет собственные файлы и UCI; Zapret2 не удаляет и не останавливает. Общие зависимости и вручную размещённые ключи остаются. Альтернатива: скачать `uninstall.sh` из этого репозитория и выполнить от root.
