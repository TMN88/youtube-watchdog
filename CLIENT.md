# Отдельный диагностический LAN-клиент

Без него используйте `mode=safe`: карточка «YouTube · роутер» показывает локальное измерение, поле client_youtube остаётся UNKNOWN, восстановление запрещено. Указание `mode=ssh` без `client_confirmed=1`, валидного частного IPv4, ключа и known_hosts также не разрешает восстановление.

Подходящий клиент — отдельный Linux/OpenWrt-хост в нужном LAN/VLAN, который действительно ходит через этот роутер. **Это не сам роутер, не VPS, не Tailscale-адрес и не устройство с собственным VPN/прокси/другим шлюзом.** Клиент должен попадать в те же правила Zapret2, DNS и маршрутизации, что проверяемая группа устройств. Если разные VLAN/исключения имеют разные правила, один клиент характеризует только свою группу.

Автоматически доказать соответствие политик всех устройств невозможно. Если путь не подтверждён оператором или есть сомнения, оставьте безопасный режим. `client_confirmed` — явное подтверждение оператора, а не автоматическое обнаружение.

1. На клиенте установите curl, CA, `timeout` и `nslookup`, а также SSH-сервер. Скопируйте **неизменённый** `files/probe.sh` из этого выпуска в `/usr/libexec/youtube-watchdog-probe`, владельцем root, права 755. Скрипт можно проверить вручную: он выводит ровно одну строку HEALTHY, YOUTUBE_DOWN, NETWORK_DOWN, DNS_DOWN или UNKNOWN.
2. Создайте отдельного пользователя SSH `watchdog` с доступом только к этой команде. Используйте отдельную пару ключей, не ключ управления роутером. На OpenSSH ограничьте публичный ключ в `authorized_keys` строкой `restrict,command="/usr/libexec/youtube-watchdog-probe"` перед самим ключом. Конкретная настройка учётной записи зависит от дистрибутива; у пользователя должна быть возможность выполнить эту фиксированную команду без интерактивной авторизации. Dropbear требует своих эквивалентных ограничений.
3. На роутере установите **openssh-client** через его пакетный менеджер, если планируете этот режим. Разместите приватный ключ в `/etc/youtube-watchdog/client_key` (root:root, 600), проверенный ключ клиента — в `/etc/youtube-watchdog/known_hosts` (600). Сверьте fingerprint с консолью клиента или другим доверенным каналом; слепой `ssh-keyscan` не подтверждает подлинность. Каталог — 700. Служба не создаёт и не скачивает ключи и не отключает StrictHostKeyChecking.
4. Убедитесь, что HTTPS с клиента идёт по нужному клиентскому пути через роутер: проверьте шлюз, DNS и отсутствие собственного VPN, прокси, policy routing, исключений из Zapret2. Сам роутер должен достигать клиента именно через LAN. Не включайте режим по одному лишь успешному SSH-входу.
5. После подтверждения задайте **фактический** частный IPv4 клиента (адрес ниже — только пример):

```sh
uci set youtube-watchdog.main.mode='ssh'
uci set youtube-watchdog.main.client_host='192.168.1.2'
uci set youtube-watchdog.main.client_user='watchdog'
uci set youtube-watchdog.main.client_confirmed='1'
uci commit youtube-watchdog
youtube-watchdog check
youtube-watchdog status
```

Однократный `check` не вызывает перезапуск. Для применения фоновой службой сразу выполните `/etc/init.d/youtube-watchdog restart`. Не создавайте искусственные сбои на рабочем роутере для проверки.

SSH запускает только фиксированный `/usr/libexec/youtube-watchdog-probe`. Разрешены literal RFC1918 IPv4 (10/8, 172.16/12, 192.168/16), имя пользователя ограничено буквами, цифрами, `_` и `-`. SSH не читает пользовательский ssh_config, не использует пароль и требует проверенный host key. Общий таймаут клиента — 65 секунд. Любой посторонний вывод, сбой SSH, timeout, неизвестная/неполная строка приводит к UNKNOWN и запрещает восстановление. Сбой локальной контрольной проверки — дополнительное вето.

Возврат в безопасный режим:

```sh
uci set youtube-watchdog.main.mode='safe'
uci set youtube-watchdog.main.client_confirmed='0'
uci commit youtube-watchdog
/etc/init.d/youtube-watchdog restart
```

Публичный/приватный ключ, адрес вашего клиента и пароль никогда не нужно добавлять в GitHub-репозиторий.
